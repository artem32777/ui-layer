## Заголовок и описание

Передавайте краткий результат первым аргументом, а пояснение — через `description`:

```ts
const { $toast } = useNuxtApp()

$toast.success('Файл сохранён', {
	description: 'Изменения доступны всем участникам проекта',
})
```

## Действие

Через `action` можно добавить одну короткую операцию, связанную с уведомлением:

```ts
$toast('Запись удалена', {
	action: {
		label: 'Отменить',
		onClick: () => restoreRecord(),
	},
})
```


## Асинхронная операция

`$toast.promise` автоматически меняет состояние уведомления после завершения асинхронной операции:

```ts
const request = $fetch('/api/profile', {
	method: 'POST',
	body: form,
})

$toast.promise(request, {
	loading: 'Сохраняем профиль',
	success: 'Профиль сохранён',
	error: 'Не удалось сохранить профиль',
})
```

`success` и `error` также принимают функции, которым передаётся результат Promise или ошибка.

## Время отображения

```ts
$toast.info('Настройки обновлены', { duration: 10_000 })
$toast.loading('Ожидаем ответ', { duration: Infinity })
```

- `duration` задаётся в миллисекундах.
- `Infinity` оставляет уведомление на экране до программного закрытия.
- Для обычных уведомлений предпочтительна стандартная длительность контейнера.

## Программное закрытие

Каждый вызов возвращает идентификатор уведомления:

```ts
const toastId = $toast.loading('Загружаем данные', {
	duration: Infinity,
})

$toast.dismiss(toastId)
$toast.dismiss() // закрыть все уведомления
```

## Обработка закрытия

```ts
$toast('Сообщение', {
	onDismiss: toast => trackDismiss(toast.id),
	onAutoClose: toast => trackAutoClose(toast.id),
})
```

- `onDismiss` вызывается после ручного закрытия или свайпа.
- `onAutoClose` вызывается после автоматического закрытия по таймеру.

## Настройка отдельного уведомления

Для отдельного уведомления доступны `class`, `descriptionClass`, `classes`, `style`, `unstyled`, `icon`, `position`, `closeButton` и `dismissible`:

```ts
$toast.warning('Проверьте данные', {
	closeButton: true,
	position: 'top-center',
	class: 'profile-warning',
})
```

Используйте индивидуальные стили только для отдельного продуктового сценария. Общий внешний вид настраивается централизованно в `Toast.vue`.

## Создание кастомного тоста

Если стандартных вариантов `$toast.success` и других недостаточно, создайте отдельный публичный метод, например `$toast.favorite`. Внутри такого метода используется `vueSonnerToast.custom`. Кастомный тост состоит из двух соседних файлов внутри своего feature:

- Vue-компонент содержит разметку, иконки и scoped-стили;
- TypeScript-файл вызывает `vueSonnerToast.custom`, передаёт props и добавляет новый публичный метод в API toast.

Например, структура тоста избранного:

```text
components/add-to-favorite/toast/
├── FavoriteToast.vue
└── favoriteToast.ts
```

### Компонент тоста

Компонент принимает только необходимые для отображения данные. Вся его стилизация остаётся рядом с разметкой:

```vue
<script setup lang="ts">
import { Icon } from '#layers/ui/app/modules/svg-icon'
import type { FavoriteAction } from './favoriteToast.ts'

defineProps<{
	action: FavoriteAction
}>()
</script>

<template>
	<div class="favorite-toast">
		<Icon :name="action === 'add' ? 'star' : 'close'" />
		<span class="favorite-toast__text">
			{{ action === 'add' ? 'Добавлено в избранное' : 'Удалено из избранного' }}
		</span>
	</div>
</template>

<style scoped lang="scss">
.favorite-toast {
	display: flex;
	align-items: center;
	gap: 10px;
	padding: 12px 16px;
	border-radius: 8px;
	color: #ffffff;
	background-color: #000000;
}
</style>
```

### Новый метод toast

Расширяйте исходный singleton из `vue-sonner` через `Object.assign`. Компонент обязательно передавайте через `markRaw`, иначе Vue сделает его реактивным и выведет warning о лишних накладных расходах:

```ts
import { toast as vueSonnerToast } from 'vue-sonner'
import { markRaw } from 'vue'
import FavoriteToast from './FavoriteToast.vue'

export type FavoriteAction = 'add' | 'remove'

export const favoriteToast = Object.assign(vueSonnerToast, {
	favorite(action: FavoriteAction) {
		return vueSonnerToast.custom(markRaw(FavoriteToast), {
			componentProps: { action },
			position: 'bottom-center',
		})
	},
})
```

`componentProps` передаёт props в компонент, а остальные параметры соответствуют обычным опциям `vue-sonner`: `position`, `duration`, `dismissible`, `closeButton` и другим.

### Подключение к `$toast`

Модуль `vue-sonner/nuxt` уже регистрирует `$toast`, поэтому нельзя повторно возвращать `provide: { toast }`: Nuxt завершит инициализацию с ошибкой `Cannot redefine property: $toast`.

Импортируйте расширенный singleton в проектном Nuxt-плагине. Generic плагина добавит новый метод в тип `$toast`, а импорт выполнит расширение исходного объекта до его использования:

```ts
import { defineNuxtPlugin } from '#imports'
import { favoriteToast } from '~/modules/premises/components/add-to-favorite/toast/favoriteToast'

export default defineNuxtPlugin<{ toast: typeof favoriteToast }>(() => {
	void favoriteToast
})
```

После этого кастомный метод вызывается так же, как стандартные виды:

```ts
import { useNuxtApp } from '#imports'

const { $toast } = useNuxtApp()

$toast.favorite('add')
$toast.favorite('remove')
```

Вызывайте `useNuxtApp()` только внутри Vue setup-функции, Nuxt-плагина, middleware или composable. Вызов на верхнем уровне импортируемого модуля выполняется без активного Nuxt-контекста и приводит к ошибке `A composable that requires access to the Nuxt instance was called outside of a plugin`.
