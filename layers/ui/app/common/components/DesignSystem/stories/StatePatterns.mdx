# Паттерны ошибок и пустых состояний

Пустые состояния и ошибки лучше документировать как отдельные паттерны: они часто повторяются в разных страницах, но ломаются первыми при спешке.

<Canvas of={DesignSystemStories.StatePatterns} />

## Пустое состояние

- Пишем, что именно отсутствует.
- Объясняем, почему пользователь это видит, если причина важна.
- Даём одно главное действие, если пользователь может исправить ситуацию.
- Не показываем технические детали вместо понятного текста.

## Ошибка

- Описываем проблему человеческим языком.
- Не обвиняем пользователя.
- Показываем следующий шаг: повторить, изменить данные, обратиться в поддержку.
- Цвет ошибки берём из `var(--red)`, а не из локального hex.

## Примеры текстов

```txt
Пусто: Пока нет добавленных элементов.
Действие: Добавить элемент

Ошибка: Не удалось загрузить данные.
Действие: Повторить
```
